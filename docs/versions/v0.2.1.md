# v0.2.1

发布日期:2026-09-07

## Added

- 端到端基准套件(gateway)新增 `tcp_room` 规模梯度:单房间广播 8/32/64/256 人(一次迭代 = 一条聊天触达全体成员)、多连接并发心跳 `tcp_concurrency` 8/32/64/256 条已绑定连接的全量 tick。
- 新增 `footprint` 连接内存足迹基准(非 criterion,阶梯建连 + 快照报告):64/128/256 常驻 TLS 连接的 RSS 与活跃堆分配双指标(macOS `proc_pidinfo` / Linux `/proc/self/statm` + 全局计数分配器),实测 ~28KiB 堆 / ~37KiB RSS 每连接(含客户端与服务端两端)。
- 基准公共装置 `crates/gateway/benches/support/`:进程 fd 上限提升(`raise_fd_limit`)、`ConnectGate` 固定建连并发闸门(64 < macOS `kern.ipc.somaxconn=128`)、看门狗超时(`watchdog`)、`SO_LINGER=0` 建连(`tcp_connect_reuse`,防 TIME_WAIT 耗尽临时端口)。
- net-kit 接入管线新增 `AcceptLoopConfig` 与 `accept_loop_with`:TLS 握手由多个 accept worker 并行消化,突发建连时即时排空内核 accept 队列;原 `accept_loop` 语义不变(兼容旧调用)。
- 新配置项 `SERVER_ACCEPT_CONCURRENCY`(默认 256,`.public_env` 同步):服务端 TLS 握手并行度。

## Changed

- 房间人数上限回归单一参数:`APP_MAX_PLAYERS_PER_ROOM`(默认 64)直接决定房间容量,移除领域层 1024 硬上限钳制;单主城地图类玩法可将该值调到数千(PRD 18 表同步)。
- `Room` 聚合 `open` 对非法容量(0)收敛为 1,其余按配置原样生效。
- 端到端基准档位上限定为 256 连接:1024+ 档位在本机(单进程双端、临时端口区间有限)实测出现事件缺口与建连失败,明确不在常规套件内(AGENTS 10.9 记录在案)。

## Fixed

- 修复基准建连闸门 permit 随连接生命周期持有导致的死锁:第 65 个建连起永久阻塞,所有 ≥128 的档位无法完成。
- 修复基准心跳客户端绑定后常驻循环占住闸门任务体,导致 `gate.run` 永久等待、并发心跳档位装配死锁的问题(绑定完成即转交常驻 task 并返回)。
- 修复 `footprint` 基准误丢 shutdown 发送端,accept 循环把通道关闭当作停机、监听器提前关闭的问题。
- 修复高频建连-关闭基准在 TIME_WAIT 占满临时端口后全线 `EADDRNOTAVAIL` 的问题(客户端 `SO_REUSEADDR` + `SO_LINGER=0`)。
- Room Actor 广播丢弃事件时补充 debug 日志,便于定位慢消费者。
