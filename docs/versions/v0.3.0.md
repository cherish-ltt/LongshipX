# v0.3.0

发布日期:2026-11-03

本版本合入 PR #19-#33,修复 bug issue #2-#18 及 4 项安全问题;KCP 增强需求 #1 不在本次范围内。

## Fixed

- 注册账号与玩家在同一事务中创建,失败或提交前取消不再留下半套数据;并发重名由唯一约束拒绝。注册审计保存归一化用户名与独立玩家标识,不记录密码或令牌。([#23](https://github.com/cherish-ltt/LongshipX/pull/23)、[#19](https://github.com/cherish-ltt/LongshipX/pull/19))
- 登录原子替换同玩家的全部旧令牌,存储失败不再继续签发成功;并发登录结束后最多一个令牌有效。([#22](https://github.com/cherish-ltt/LongshipX/pull/22))
- 已绑定 TCP 连接在业务请求与房间广播前重新校验原令牌;撤销、过期、存储错误或校验超时均关闭连接。([#25](https://github.com/cherish-ltt/LongshipX/pull/25))
- TLS 握手前执行连接与单 IP 未鉴权配额准入,固定期限覆盖握手和 Bind;无效 Bind 不能延长期限,失败或取消归还配额。([#26](https://github.com/cherish-ltt/LongshipX/pull/26))
- 玩家经验原子更新,登录只更新登录时间,不再覆盖并发成长;升级事件仅在持久化提交后发布。([#27](https://github.com/cherish-ltt/LongshipX/pull/27))
- Argon2 计算移至有界阻塞任务,不再阻塞异步调度线程;超限立即返回 Busy/HTTP 503,请求取消不会提前释放仍在计算的名额。([#31](https://github.com/cherish-ltt/LongshipX/pull/31))
- 单连接必须显式离房后才能切换房间;重复加入当前房间幂等。离房可靠入队并等待完成回执,最后成员离开后立即回收空房间。([#28](https://github.com/cherish-ltt/LongshipX/pull/28)、[#29](https://github.com/cherish-ltt/LongshipX/pull/29))
- Actor 事件队列与 socket 出站队列满时可靠断开连接,不再静默丢失关键回执后继续会话。([#32](https://github.com/cherish-ltt/LongshipX/pull/32))
- 监听器持续回收已完成连接任务,不取消正在进行的 accept/TLS;停机先协作退出,超时后由 RAII 清理资源,阻塞 socket 写入的排空时间有界。([#30](https://github.com/cherish-ltt/LongshipX/pull/30)、[#33](https://github.com/cherish-ltt/LongshipX/pull/33))
- 启动配置拒绝零容量房间命令队列;TLS 路径支持 `~/` 展开;HTTP 308 跳转使用实际 HTTPS 端口并保留 IPv6、路径与查询,缺失或非法 Host 返回 400。([#21](https://github.com/cherish-ltt/LongshipX/pull/21)、[#20](https://github.com/cherish-ltt/LongshipX/pull/20)、[#24](https://github.com/cherish-ltt/LongshipX/pull/24))

## Added

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `APP_PASSWORD_MAX_CONCURRENCY` | `2` | 同一共享哈希器中 hash/verify 的合计并发上限,超限不排队 |
| `SERVER_WRITE_DRAIN_TIMEOUT_MS` | `1000` | 发送端全部关闭后写队列排空期限(毫秒),0 表示不等待 |

## Changed

- workspace、全部 8 个 crate、内部精确版本约束与锁文件统一为 `0.3.0`;未升级第三方依赖,未修改 protobuf 字段或数据库 schema。
- `PasswordHasher::hash/verify` 改为异步端口,调用方须 `.await`;`Argon2PasswordHasher::new` 增加第四个参数(计算并发上限)。
- `RegisterUseCase::new` 第二个参数改为 `Arc<dyn RegistrationStore>`,生产使用 `SeaRegistrationStore`,内存装置使用 `InMemoryRegistrationStore`;外部注册实现须保证两条记录的原子性。
- `PlayerRepository` 增加原子 `gain_exp` 与定向 `record_login`;事件发布失败使用 `AppError::PostCommit`,表示数据已提交,调用方不得重试整个奖励。
- `SessionTokenStore::create` 契约改为原子替换同玩家旧会话,自定义存储实现须遵循相同语义。
- 房间订阅使用 `RoomEventSink`,调用方应保留 sink 并观察 `failed()`;`RoomCommand::Leave` 增加完成回执,`leave/leave_all` 等待清理完成。`OutboundSender` 溢出后永久不可写。
- `TcpGatewayConfig` 增加 `shutdown_timeout`/`write_drain_timeout`,`ConnectionConfig` 增加 `write_drain_timeout`,`AcceptLoopConfig` 增加 `shutdown_timeout`;自定义配置装配须补齐字段。
- `redirect_router`/`serve_redirect` 调用方须传入实际 HTTPS 端口;`SERVER_UNAUTH_TIMEOUT_SECS` 现在覆盖 TLS 前准入至 Bind 完成的整个固定期限,`APP_SHUTDOWN_TIMEOUT_SECS` 控制处理器协作退出期限。

## 验证与边界

- 发布前修复组合已通过 188 项默认测试、4 项独立 PostgreSQL/Redis 回归、格式检查、全目标 Clippy 与构建;全仓行覆盖 89.99%(5096/5663),不包含单独执行的真实库回归。
- 逐项合并后的文件树与已验证组合一致;本次版本更新按维护者要求不重跑测试、构建、Clippy、覆盖率或性能基准。
- 不清理历史孤立注册数据;提交后网络中断可能使注册结果未知,重试可能返回用户名冲突。会话替换超时也不能解释为旧会话未变更。
- Redis 原子替换使用单实例 Lua 脚本,不支持跨槽 Redis Cluster。未引入 outbox,已提交数据的事件仍可能投递失败,需业务侧处理。
- 已接收的请求及已入发送队列的数据不会因后续令牌撤销而撤回;无流量失效连接最迟按心跳超时清理。强制退出期限不保证未提交业务或未送达通知完成。
- server-bin 完整启动链路、目标生产部署、公网与跨平台验收未覆盖;性能表沿用历史数据,不作为 v0.3.0 重测结果。
